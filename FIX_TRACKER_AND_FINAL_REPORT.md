## 5. Duplicate Handling Policy & Discrepancy Mathematics

### Deduplication Policy
- **Implementation**: In `backend/app/transformation/canonical.py:463`, deduplication is performed using `canonical_df.unique(subset=["equipment_id", "timestamp_utc"], keep="last").sort("timestamp_utc")`.
- **Audit Findings**:
  - In File 1 (`F2_AHU02_North.csv`), exactly 44 duplicate timestamps exist (72 rows total).
  - Among these duplicate timestamps, exactly 7 redundant rows in the raw CSV were in the faulted condition for `FC1`.
  - When UPDATED-FDD ingests the dataset, `keep='last'` drops these 7 duplicate fault rows.
  - Calculation: $555\text{ raw samples} - 7\text{ duplicate samples} = 548\text{ retained samples}$.
  - $548 \times \frac{5}{60} = 45.6667\text{ hours} \approx 45.67\text{ hours}$.
  - Open-FDD's Pandas cookbook retained all duplicate rows ($555 \times \frac{5}{60} = 46.25\text{ hours}$).
  - For `CMD-1`, both systems detect exactly 31 contiguous episodes starting and ending at identical timestamps. The 4-sample duration difference ($149.93\text{h}$ vs $148.58\text{h}$) is due to continuous interval delta integration ($\sum \Delta t_i$) vs discrete SQL window multiplication ($N \times \frac{300}{3600}$).
